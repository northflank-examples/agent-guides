# How to deploy a LangGraph agent

To deploy a LangGraph agent, build an Agent Server image from your `langgraph.json` with the LangGraph CLI, run it on port 8000 next to PostgreSQL (`DATABASE_URI`) and Redis (`REDIS_URI`), pass `LANGSMITH_API_KEY` or a licence key and your model keys at runtime, and put authentication in front of the API. The server ships with no auth of its own, so an open URL lets anyone spend your model credits.

This guide does it on Northflank with the CLI: a Dockerfile generated by `langgraph dockerfile`, managed Postgres and Redis addons linked through one secret group, and a service built from your repo with basic auth on its public port. You end with an HTTPS endpoint where `/ok` returns `{"ok":true}` and a run completes through `/runs/wait`. Every step is a command a developer or a coding agent (Claude Code, Codex, Cursor) can run as-is; a human logs in once, shares the repository with Northflank and supplies the LangSmith key.

## TL;DR: how to deploy a LangGraph agent

1. Install the CLI with `npm install -g @northflank/cli` and run `nf login`.
2. Check that the repo has a `langgraph.json` and the `langgraph` dependency, confirm the team, repository, branch and project, and give Northflank access to the repository.
3. Generate a `Dockerfile` with `langgraph dockerfile -c langgraph.json Dockerfile` and push it.
4. Create a project, Postgres and Redis, and a secret group that links `DATABASE_URI` and `REDIS_URI` next to `LANGSMITH_API_KEY` and your model key.
5. Deploy with `northflank put service combined` on port 8000, a readiness probe on `/ok` and basic-auth credentials on the public port.
6. Check that the live build is your pushed commit, `/ok` returns `{"ok":true}`, your graph appears in `/assistants/search`, a run completes, and a request without credentials gets 401.

## Why the Agent Server, and what it needs

LangGraph itself is an open-source library. You can import a compiled graph into any Python web app. LangChain's **Agent Server** (formerly LangGraph Server) wraps your graphs in a ready-made HTTP API with assistants, threads, background runs, streaming and checkpointing. Its standalone deployment docs list what it needs:

- **`DATABASE_URI`**: PostgreSQL for assistants, threads, runs, thread state, long-term memory and the task queue.
- **`REDIS_URI`**: Redis as the pub/sub broker that streams output from background runs.
- **`LANGSMITH_API_KEY`** and **`LANGGRAPH_CLOUD_LICENSE_KEY`**: the licence key is checked once at startup, and the server needs outbound access to `https://beacon.langchain.com`.

Two caveats from the same page. LangChain calls its Docker examples development setups and recommends Kubernetes with its Helm chart for production, so on any other platform, queue scaling and graceful run draining are yours to manage. It also warns against serverless hosting, because scale-to-zero can lose background tasks.

That decides where to deploy a LangGraph agent: an always-on container next to Postgres and Redis, with outbound internet access. A Kubernetes cluster running the Helm chart is the path LangChain tests. A container platform with managed databases runs the same image with less to operate. If the licence terms don't suit you, wrap the graph in your own FastAPI app instead (see the FAQ).

## Prerequisites

- **A LangGraph app that runs locally** with the LangGraph CLI (`pip install -U "langgraph-cli[inmem]"`). This starts it; stop it with Ctrl+C:
  ```bash
  langgraph dev --no-browser
  ```
- **The code is in a GitHub, GitLab or Bitbucket repository** that you can push to.
- **Node.js 22.13 or later** (for the Northflank CLI) and **`jq`** (to read the CLI's JSON output).
- **A Northflank account.** [Sign up](https://app.northflank.com/signup) if you don't have one.
- **A LangSmith API key** (and `LANGGRAPH_CLOUD_LICENSE_KEY` if you have one) and a model key such as `OPENAI_API_KEY`, exported in your shell. Confirm that your LangSmith plan covers self-hosted Agent Servers.

## Step 1: Install the Northflank CLI and log in

```bash
npm install -g @northflank/cli@latest
nf login
set -o pipefail
northflank get auth -o json | jq -r '(.data // .).entityId'
```

**This step needs a human:** `nf login` opens a browser, where you sign in and pick the team to deploy into. The last command prints that team's ID, so you know the CLI is logged in to the right place. `set -o pipefail` makes a failed `northflank` command show up as a failure even when its output is piped into `jq`; keep it on for the rest of this guide. On a machine without a browser, such as CI, create a team API token in the Northflank UI and run `nf login --name ci --token "$NF_API_TOKEN"` instead.

If you're a coding agent (Claude Code, Codex, Cursor or OpenCode), also run `nf agent setup --agent claude --yes`, replacing `claude` with your agent. It installs the Northflank skill and MCP server, which load in your next session. This guide works without them.

## Step 2: Check the app and confirm where it will deploy

Before changing anything, confirm that this guide fits the app and print the deployment target. Run this from the repository root:

```bash
jq -r '"graphs: \(.graphs // {} | keys | join(", "))  dependencies: \(.dependencies // [] | join(", "))"' langgraph.json
grep -hiE '^[[:space:]"]*langgraph' $(ls requirements.txt pyproject.toml 2>/dev/null) /dev/null || echo "langgraph: missing"
ls requirements.txt pyproject.toml uv.lock poetry.lock Dockerfile 2>/dev/null
[ -n "$LANGSMITH_API_KEY" ] && echo "LANGSMITH_API_KEY: set" || echo "LANGSMITH_API_KEY: missing"
[ -n "$OPENAI_API_KEY" ] && echo "OPENAI_API_KEY: set" || echo "OPENAI_API_KEY: missing"

echo "team:    $(northflank get auth -o json | jq -r '(.data // .).entityId')"
echo "repo:    $(git remote get-url origin)"
echo "branch:  $(git branch --show-current)"
northflank get project --projectId langgraph-agent -o json >/dev/null 2>&1 \
  && echo "project: langgraph-agent exists and will be reused" \
  || echo "project: langgraph-agent will be created"
```

- If `langgraph.json` doesn't exist or `langgraph` says `missing`, this isn't a LangGraph app. Stop and use a guide for your framework.
- The `dependencies` entry (usually `"."`) tells the Agent Server image where to install your package from; the lockfile tells you which package manager the project uses.
- If a `Dockerfile` already exists, compare it with step 5 before replacing it.
- If a key says `missing`, ask the user to export it. Never print its value. Swap `OPENAI_API_KEY` for the model key your graph reads.
- If the remote is an SSH address (`git@github.com:owner/repo.git`), use its HTTPS form (`https://github.com/owner/repo`) in the steps below.

**If you're an agent:** show the user the team, repository, branch, region (`europe-west` below, unless they choose another) and whether the project is new or reused. Wait for them to confirm before you create anything.

## Step 3: Give Northflank access to your repository

**This step needs a human, once per repository.** Open the [Git integrations page](https://app.northflank.com/s/account/integrations/vcs) and click **Link GitHub** (or GitLab or Bitbucket). When GitHub asks which repositories to share, include this one. If the account is already linked, select it and click **Edit installation** to add the repository. Public repositories need no access. See [link your Git account](https://northflank.com/docs/v1/application/getting-started/link-your-git-account).

## Step 4: Create a project and check repository access

A project holds your services. Pick the region closest to your users (`northflank list regions` lists them); it can't be changed later. Skip the `create` line if step 2 said the project will be reused. `create` fails if the name is taken, so it never changes a project you didn't mean to touch.

```bash
northflank create project -o json --input '{ "name": "langgraph-agent", "region": "europe-west" }'
export PROJECT_ID=langgraph-agent

northflank get service repository-access --projectId "$PROJECT_ID" --noDefaults -o json --input '{
  "projectUrl": "https://github.com/<OWNER>/<REPO>", "projectType": "github", "projectBranch": "main"
}' | jq '(.data // .) | {accessible, reason}'
```

Use your repository's URL and branch, and `gitlab` or `bitbucket` as the `projectType` if that's where it lives. Continue when `accessible` is `true`. If it's `false`, Northflank can't see the repository yet: go back to step 3.

## Step 5: Generate the `Dockerfile`

The repo needs a working `langgraph.json` that `langgraph dev` runs locally. A minimal one:

```json
{
  "dependencies": ["."],
  "graphs": { "agent": "./src/agent/graph.py:graph" },
  "env": ".env"
}
```

Keep `.env` out of Git. Its values go into the secret group instead.

Generate the `Dockerfile`, and re-run this whenever `langgraph.json` changes. Northflank builds what's in your repository, not the files on your machine, so commit and push it:

```bash
pip install -U langgraph-cli
langgraph dockerfile -c langgraph.json Dockerfile
git add Dockerfile
git commit -m "Add Northflank deployment files"
git push
```

The base image is `langchain/langgraph-api`. Pin it with `base_image` in `langgraph.json` if you want repeatable builds.

Names used below: addons `lg-db` and `lg-redis`, secret group `langgraph-env`, service `langgraph`.

## Step 6: Create Postgres and Redis

```bash
northflank put addon --projectId "$PROJECT_ID" --noDefaults -o json --input '{
  "name": "lg-db", "type": "postgresql", "version": "16-latest",
  "tlsEnabled": false, "externalAccessEnabled": false,
  "billing": { "deploymentPlan": "nf-compute-50", "storage": 6144, "replicas": 1 }
}'
northflank put addon --projectId "$PROJECT_ID" --noDefaults -o json --input '{
  "name": "lg-redis", "type": "redis", "version": "7-latest",
  "tlsEnabled": false, "externalAccessEnabled": false,
  "billing": { "deploymentPlan": "nf-compute-20", "storage": 4096, "replicas": 1 },
  "typeSpecificSettings": { "redisMaxMemoryPolicy": "noeviction", "redisSentinelEnabled": false }
}'

ADDONS_OK=1
for A in lg-db lg-redis; do
  OK=0
  for i in $(seq 1 90); do
    S=$(northflank get addon --projectId "$PROJECT_ID" --addonId "$A" --noDefaults -o json | jq -r '(.data // .).status')
    echo "$A=$S"
    case "$S" in running) OK=1; break;; failed|error|errorAllocating|deleting|deleted) echo ADDON_FAILED; break;; esac
    sleep 10
  done
  [ "$OK" = 1 ] || ADDONS_OK=0
done
[ "$ADDONS_OK" = 1 ] || { echo "ADDONS_NOT_READY: stop here and read the addon status"; false; }
```

Don't continue to step 7 if the last line printed `ADDONS_NOT_READY`.

Both addons only accept traffic from inside the project, so TLS is off to keep the connection URIs plain. `noeviction` stops Redis from silently dropping stream data when memory fills. Storage can only grow later.

## Step 7: Create the secret group

Build the JSON with `jq --arg` so no key appears on the command line:

```bash
jq -n --arg ls "$LANGSMITH_API_KEY" --arg lic "${LANGGRAPH_CLOUD_LICENSE_KEY:-}" --arg oai "$OPENAI_API_KEY" '{
  name: "langgraph-env", type: "secret", secretType: "environment", priority: 10,
  restrictions: { restricted: false },
  addonDependencies: [
    { addonId: "lg-db",    keys: [ { keyName: "POSTGRES_URI",     aliases: ["DATABASE_URI"] } ] },
    { addonId: "lg-redis", keys: [ { keyName: "REDIS_MASTER_URL", aliases: ["REDIS_URI"] } ] }
  ],
  secrets: { variables: ({ LANGSMITH_API_KEY: $ls, OPENAI_API_KEY: $oai }
                         + (if $lic == "" then {} else { LANGGRAPH_CLOUD_LICENSE_KEY: $lic } end)) }
}' > langgraph-env.json
northflank put secret --projectId "$PROJECT_ID" --noDefaults -o json --file langgraph-env.json >/dev/null && rm langgraph-env.json
```

Add any other variables your graph reads (`ANTHROPIC_API_KEY`, `TAVILY_API_KEY`…) to `variables`.

## Step 8: Check the Redis link

```bash
northflank get secret-link --projectId "$PROJECT_ID" --secretId langgraph-env --addonId lg-redis --noDefaults -o json \
  | jq '(.data // .) | {linked, linkedKeys, availableKeys}'
```

If `linkedKeys` is empty, pick the URL key from `availableKeys` (usually `REDIS_MASTER_URL`), re-link it as `REDIS_URI` and run the check again:

```bash
northflank update secret-link --projectId "$PROJECT_ID" --secretId langgraph-env --addonId lg-redis --noDefaults -o json \
  --input '{"keys":[{"keyName":"<KEY>","aliases":["REDIS_URI"]}]}'
```

## Step 9: Deploy the Agent Server

Generate a password for the port's basic auth, then write the service definition to `lg-service.json` and create the service:

```bash
LG_BASIC_PW=$(openssl rand -hex 24)
jq -n --arg pw "$LG_BASIC_PW" '{
  name: "langgraph",
  billing: { deploymentPlan: "nf-compute-100-2" },
  deployment: { instances: 1, docker: { configType: "default" } },
  vcsData: { projectUrl: "https://github.com/<OWNER>/<REPO>", projectType: "github", projectBranch: "main" },
  buildSettings: { dockerfile: { buildEngine: "buildkit", dockerFilePath: "/Dockerfile", dockerWorkDir: "/" } },
  ports: [ { name: "http", internalPort: 8000, public: true, protocol: "HTTP",
             security: { credentials: [ { username: "agent", password: $pw, type: "basic-auth" } ] } } ],
  healthChecks: [
    { protocol: "HTTP", type: "readinessProbe", path: "/ok", port: 8000,
      initialDelaySeconds: 10, periodSeconds: 10, timeoutSeconds: 3, failureThreshold: 6, successThreshold: 1 },
    { protocol: "HTTP", type: "livenessProbe", path: "/ok", port: 8000,
      initialDelaySeconds: 60, periodSeconds: 20, timeoutSeconds: 3, failureThreshold: 3 }
  ]
}' > lg-service.json
northflank put service combined --projectId "$PROJECT_ID" --noDefaults -o json --file lg-service.json && rm lg-service.json
```

What the settings do:

- **`vcsData`** uses the same repository URL, provider and branch as in step 4.
- **`billing.buildPlan`** is optional; leave it out to use the default build plan, and only set it if builds run out of memory, using a build plan your team has access to (an unavailable one fails with `Build plan not found`).
- **Port 8000** is where the Agent Server listens inside its container (LangChain's Docker example maps it with `-p 8123:8000`).
- **`/ok`** is the health route from the standalone docs, and it returns `{"ok":true}`. Health probes run inside the cluster, so the port's credentials don't block them.
- **`security.credentials`** puts HTTP basic auth on every public hostname of the port. The password is stored in the service definition. Give it to the user and keep it in this shell for the checks.
- **One instance.** Several instances can share Postgres and Redis, but LangChain's scaling guidance (separate queue workers, run draining) was written for its Helm chart. Scale up only after you've read it.

## Step 10: Wait for the build and rollout

```bash
OK=0
for i in $(seq 1 120); do
  S=$(northflank get service --projectId "$PROJECT_ID" --serviceId langgraph --noDefaults -o json)
  B=$(echo "$S" | jq -r '(.data // .).status.build.status // "NONE"')
  D=$(echo "$S" | jq -r '(.data // .).status.deployment.status // "NONE"')
  echo "build=$B deployment=$D"
  case "$B" in FAILURE|CRASHED|ABORTED|SUBMISSION_FAILURE) echo BUILD_FAILED; break;; esac
  [ "$D" = "FAILED" ] && { echo DEPLOY_FAILED; break; }
  [ "$B" = "SUCCESS" ] && [ "$D" = "COMPLETED" ] && { OK=1; break; }
  sleep 10
done
[ "$OK" = 1 ] || { echo "ROLLOUT_NOT_COMPLETE: stop here and read the build or deployment logs"; false; }

if [ "$OK" = 1 ]; then
  HOST=$(northflank get service --projectId "$PROJECT_ID" --serviceId langgraph --noDefaults -o json \
    | jq -r '[(.data // .).ports[]? | select(.public == true) | .dns // empty][0] // empty')
  # Older API responses only list the host on the deprecated ports endpoint
  [ -n "$HOST" ] || HOST=$(northflank get service ports --projectId "$PROJECT_ID" --serviceId langgraph --noDefaults -o json \
    | jq -r '(.data // .).ports[] | select(.public == true) | .dns' | head -n1)
  echo "https://$HOST"
fi
```

`COMPLETED` means rolled out and serving. Don't continue if the guard printed `ROLLOUT_NOT_COMPLETE`; read the build logs with `northflank get service build-logs --projectId "$PROJECT_ID" --serviceId langgraph`. If the deployment stays `IN_PROGRESS`, read the startup logs:

```bash
northflank get service logs --projectId "$PROJECT_ID" --serviceId langgraph --lineLimit 100
```

## How to know it worked

You're done when all of these hold:

1. The live build is the commit you pushed. The two values should match:
   ```bash
   git rev-parse HEAD
   northflank get service builds --projectId "$PROJECT_ID" --serviceId langgraph --noDefaults -o json \
     | jq -r '(.data // .).builds | sort_by(.createdAt) | last | "\(.sha) \(.status)"'
   ```
2. The health route answers through the authenticated public URL:
   ```bash
   curl -s -u "agent:$LG_BASIC_PW" "https://$HOST/ok"        # {"ok":true}
   ```
3. A request without credentials is refused:
   ```bash
   curl -s -o /dev/null -w '%{http_code}\n' "https://$HOST/ok"  # 401
   ```
4. Your graph is registered as an assistant:
   ```bash
   curl -s -u "agent:$LG_BASIC_PW" -X POST "https://$HOST/assistants/search" \
     -H 'Content-Type: application/json' -d '{"limit": 10}' | jq -r '.[].graph_id'   # agent
   ```
5. A stateless run completes. The input shape depends on your graph's state; for a messages-based graph:
   ```bash
   curl -s -u "agent:$LG_BASIC_PW" -X POST "https://$HOST/runs/wait" -H 'Content-Type: application/json' \
     -d '{"assistant_id": "agent", "input": {"messages": [{"role": "human", "content": "Say hi"}]}}' | jq '.messages[-1].content'
   ```

From the LangGraph SDK, pass the same credentials as an `Authorization: Basic …` header when you create the client.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Logs show a licence error at startup | Key missing, wrong or not on a plan that allows self-hosting | Check `LANGSMITH_API_KEY` / `LANGGRAPH_CLOUD_LICENSE_KEY` in `langgraph-env`; ask LangChain about the plan |
| Logs show a connection error to Redis or `REDIS_URI` unset | Wrong `keyName` in the Redis link | Redo step 8 with a key from `availableKeys` |
| Build fails on `pip install` | Dependencies in `langgraph.json` don't resolve on the base image | Run `langgraph build` locally to reproduce; pin `base_image` and package versions |
| Graph changes don't show up after a push | `Dockerfile` generated from an older `langgraph.json` | Re-run `langgraph dockerfile` and commit |
| Long `/runs/wait` calls drop | Request held open through the load balancer | Create a background run on a thread and stream it, or poll the run instead of waiting |
| Readiness never passes, logs show slow imports | Work at import time in the graph module | Move clients and downloads inside functions; `FF_PROFILE_IMPORTS=true` shows the slow imports |
| Step 4 check returns `accessible: false`, or `Repository "…" not found for GitHub installation` | The repository isn't shared with Northflank | Step 3: on the Git integrations page, select the account, click **Edit installation** and add the repository. Then re-run the step 4 check |
| Check passes but the service still can't find the repo | Several Git accounts are linked and the wrong one is used | Add the check's `vcsLinkId` (in its full output) to `vcsData` as `"vcsLinkId": "<ID>"` |
| `Build plan not found` | `billing.buildPlan` names a plan your team can't use | Remove `buildPlan` to use the default |
| `northflank get auth` fails, or a command returns 401 | Not logged in, or the session expired | Run `nf login` again |
| A command is refused while `get auth` works | The API token's role lacks that permission (each command's `--help` lists it) | Use a token with that permission, or log in with `nf login` |

## A note for AI coding agents

If you're an agent running these steps for a user:

- Confirm the target from step 2 with the user before any write, and don't create the service until the step 4 check returns `accessible: true`. If it doesn't, ask the user to share the repository (step 3) instead of retrying.
- Don't report success until check 1 shows the live build is the commit you pushed.
- If the step 10 loop prints `ROLLOUT_NOT_COMPLETE`, read the build logs before changing anything.
- Never print `LANGSMITH_API_KEY`, the licence key, model keys, the addon credentials or `LG_BASIC_PW`. Build JSON with `jq --arg` and delete temp files.
- Never remove the port's `security.credentials` to make a test pass. Without them, the API is open to the internet.
- Don't accept or interpret licence terms for the user. Report a licence error and stop.
- Get explicit confirmation before deleting the addons or the service. Thread history lives in Postgres.

## FAQ

### Where should I deploy my LangGraph agent?
On something that keeps a container running with Postgres and Redis close by and allows outbound traffic for the licence check. LangChain's own production path is Kubernetes with its Helm chart. A container platform with managed Postgres and Redis, like the setup above, runs the same image with less to operate. Avoid serverless and scale-to-zero platforms, because they can lose background runs.

### Can I deploy LangGraph without the Agent Server or a LangSmith key?
Yes. The LangGraph library is open source. Wrap your compiled graph in your own FastAPI app, give it a Postgres checkpointer for thread state, and deploy it like any web service. You lose the ready-made assistants, threads and runs API, and you build streaming and background runs yourself. See [how to deploy AI agents in production](deploy-ai-agents-in-production.md) and [how to deploy a FastAPI app](deploy-fastapi-app.md).

### Can I use LangGraph's custom auth instead of basic auth?
Yes. `langgraph.json` accepts an `auth` section that points at your own handler, so you can check bearer tokens or JWTs per user. Keep the port's basic auth until that handler is deployed and tested.

### Does it need a volume?
No. All server state (threads, checkpoints, the run queue) is in Postgres, and Redis carries streams. Back up the Postgres addon instead.
